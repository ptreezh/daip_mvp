# 真实多轮辩论系统需求文档

## 项目概述

创建一个以智能助手为中心的多角色协作研究系统。用户通过与智能助手对话来发起各种类型的研究讨论，智能助手负责理解用户意图、优化提示词、邀请合适的虚拟角色、组织讨论流程，并将结果沉淀为结构化知识。

**重要发现** (基于V0.1基线分析): 项目核心组件已100%完成并通过验证，包括认知代理、制度原语、工作流引擎、共识算法等。开发重点从"构建系统"转向"集成产品"，预计开发时间从8-12周缩短至6-10天。

**核心工作流**: 用户输入 → 智能助手理解&优化 → 邀请虚拟角色 → 多角色协作讨论 → 形成共识 → 沉淀为Wiki

**支持场景**:
1. **学术研究场景**: 深度分析、系统性研究、万字级报告生成
2. **专家咨询场景**: 跨领域专家观点收集、决策支持
3. **轻松讨论场景**: 日常话题讨论、兴趣探索、闲聊互动

## 第一性原理分析

### 核心架构设计

基于现有DAIP-LIVE项目的架构分析，系统的核心组件和工作流程如下：

**智能助手层 (PersonalAssistant)**:
- 作为用户交互的统一入口
- 使用MemAgent管理用户记忆和上下文
- 使用IntentAnalysisService理解用户意图
- 负责工作流选择和参数配置

**工作流编排层 (WorkflowEngine)**:
- Critical Review Workflow: 事实验证和质量保证
- Multi-perspective Synthesis Workflow: 多角度分析和观点综合
- 支持自定义工作流的动态创建和执行

**认知代理层 (CognitiveAgent)**:
- 基于RoleManager加载的真实角色定义
- 具备独立的认知框架和推理能力
- 通过IntegratedLLMManager调用真实LLM

**知识管理层 (SSKG + WikiService)**:
- 统一的语义结构化知识图谱
- 版本化的知识存储和检索
- 自动化的知识冲突解决

### 关键设计原则

1. **单一入口原则**: 所有用户交互都通过智能助手进行，隐藏系统复杂性
2. **工作流驱动**: 基于现有的两个社会制度工作流处理不同类型的需求
3. **真实性保证**: 所有AI交互都基于真实的LLM调用和角色认知框架
4. **知识沉淀**: 所有讨论结果都自动沉淀为可复用的知识资产
5. **场景适配**: 同一套架构支持从严肃学术研究到轻松闲聊的多种场景

## 核心原则

1. **工程可用性第一**: 系统必须是一个完整的、可立即使用的单机版产品，具备稳定性和可靠性
2. **单用户单机版**: 专为个人用户设计，无需复杂的多用户管理和企业级功能
3. **真实性保证**: 所有LLM调用、角色行为、辩论过程都必须是真实的，绝不使用模拟数据
4. **基于现有实现**: 充分利用已完成的核心服务，专注于整合而非重复开发
5. **简单易用**: 提供直观的用户界面和简单的安装部署方式

## 功能需求

### 需求1: 智能助手统一入口

**用户故事**: 作为用户，我希望通过与一个智能助手对话来发起各种类型的研究讨论，助手能够理解我的需求并自动选择合适的工作流和角色。

#### 验收标准

1. WHEN 用户输入研究话题 THEN 智能助手SHALL使用MemAgent分析用户历史对话和偏好
2. WHEN 助手理解用户意图 THEN 系统SHALL使用IntentAnalysisService判断是否需要事实验证（Critical Review）或观点综合（Multi-perspective Synthesis）
3. WHEN 用户要求深度研究 THEN 助手SHALL自动选择Multi-perspective Synthesis Workflow进行系统性分析
4. WHEN 用户提供需要验证的内容 THEN 助手SHALL自动选择Critical Review Workflow进行事实检查
5. WHEN 用户要求轻松讨论 THEN 助手SHALL直接邀请相关角色进行非正式对话
6. WHEN 助手选择工作流 THEN 系统SHALL向用户说明选择理由和预期流程

### 需求2: 基于现有工作流的智能调度

**用户故事**: 作为用户，我希望智能助手能够根据我的需求自动选择和执行合适的社会制度工作流，无需我了解技术细节。

#### 验收标准

1. WHEN 用户需要事实验证 THEN 助手SHALL自动启动Critical Review Workflow，包含生成节点→事实提取节点→并行审查节点→证据汇总节点→共识计算节点→修订节点的完整流程
2. WHEN 用户需要深度分析 THEN 助手SHALL自动启动Multi-perspective Synthesis Workflow，包含任务分解节点→并行探索节点→观点综合节点的完整流程
3. WHEN 工作流执行 THEN 系统SHALL使用现有的WorkflowEngine进行节点编排和状态管理
4. WHEN 角色参与 THEN 系统SHALL使用现有的CognitiveAgent确保角色的认知独立性
5. WHEN 需要记忆管理 THEN 系统SHALL使用现有的MemAgent进行上下文优化和记忆检索
6. WHEN 生成知识 THEN 系统SHALL使用现有的WikiService进行知识沉淀和版本管理
7. WHEN 计算共识 THEN 系统SHALL使用现有的高级共识算法进行共识计算

### 需求3: 多场景适配能力

**用户故事**: 作为用户，我希望系统能够适应不同类型的讨论需求，从严肃的学术研究到轻松的日常讨论。

#### 验收标准

2. WHEN 用户指定内容长度 THEN 系统SHALL根据要求调整工作流参数，确保输出满足长度要求
3. WHEN 用户需要专家咨询 THEN 系统SHALL邀请不同领域的专家角色提供专业观点
4. WHEN 用户要求轻松讨论 THEN 系统SHALL调整角色的交流风格，支持非正式的对话模式
5. WHEN 用户要求闲聊 THEN 系统SHALL选择合适的角色进行轻松愉快的交流
6. WHEN 切换场景 THEN 系统SHALL保持上下文连贯性，通过MemAgent管理不同场景的记忆

**用户故事**: 作为用户，我希望智能助手能够记住我的偏好和历史对话，并不断优化与我的交互质量。
