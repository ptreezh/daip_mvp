# Unified Command-Line Interface - 技术架构规范

**文档状态:** 初始草案
**版本:** 0.1
**日期:** 2025-08-17
**焦点:** CLI系统架构、核心组件与设计原则。
**目标受众:** 系统架构师, CLI开发者。
**原则:** 模块化、可扩展性、可测试性。

## 1. 概述

统一命令行界面 (CLI) 是DAIP-LIVE系统与用户和自动化脚本交互的主要接口。其架构旨在提供一个健壮、高效且易于维护的工具，能够无缝集成后端服务，并支持未来的功能扩展。

## 2. 核心架构图

```
┌───────────────────────────┐
│      CLI Application      │
│    (daip-cli.py / Typer)  │
└───────────┬───────────────┘
            │
            │ Service Invocation
            ▼
┌───────────────────────────┐
│     Backend Services      │
│ (PersonalAssistantService, │
│  DebateManager, etc.)     │
└───────────────────────────┘
```

## 3. 分层架构

### 3.1 应用层 (Application Layer)
*   **Typer CLI 应用**: 作为CLI的入口点，负责解析命令行参数、路由命令到相应的处理函数。
*   **命令定义**: 使用Typer的装饰器定义命令、子命令和选项，确保清晰的命令行接口结构。

### 3.2 服务调用层 (Service Invocation Layer)
*   **后端服务客户端**: CLI命令通过此层调用DAIP-LIVE的后端服务。这可以是直接的Python函数调用（如果后端服务在同一进程空间），也可以是通过HTTP/WebSocket客户端库进行的远程调用。
*   **数据转换**: 负责将CLI参数转换为后端服务所需的输入格式，并将后端服务的响应转换为CLI友好的输出格式。

### 3.3 核心服务层 (Core Services Layer)
*   **DAIP-LIVE 后端服务**: 提供核心业务逻辑和AI能力，如个人助手、辩论管理、知识库、工作流引擎等。CLI作为这些服务的客户端。

## 4. 关键组件

### 4.1 Typer 应用框架
*   **角色**: 提供强大的命令行解析、自动生成帮助信息、参数验证和命令路由能力。
*   **优势**: 简化CLI开发，确保一致的用户体验。

### 4.2 命令模块化
*   **结构**: 顶级命令（如 `status`, `roles`）直接在 `src/cli/main.py` 中定义。子命令（如 `assistant chat`, `wiki create`）则通过Typer的 `add_typer` 机制，将相关命令组织到独立的模块中（例如 `src/cli/commands/assistant.py`, `src/cli/commands/wiki.py`）。
*   **优势**: 保持代码整洁，便于团队协作和功能扩展。

### 4.3 输入解析与验证
*   **参数与选项**: 利用Typer的强大功能，定义命令的参数和选项，支持类型提示和默认值。
*   **自定义验证**: 在命令处理函数内部或通过Typer的回调函数，实现更复杂的业务逻辑验证。

### 4.4 输出渲染
*   **Rich 库**: 利用 `rich` 库提供丰富的终端输出，包括彩色文本、表格、进度条和状态信息，提升用户体验。
*   **优势**: 使CLI输出更具可读性和专业性。

### 4.5 错误处理机制
*   **统一异常处理**: 捕获后端服务和CLI内部可能抛出的异常，并以用户友好的方式报告错误。
*   **退出码**: 根据执行结果返回标准的Shell退出码（0表示成功，非0表示失败）。

### 4.6 后端服务客户端
*   **职责**: 封装与DAIP-LIVE后端服务的交互逻辑，提供简洁的接口供CLI命令调用。
*   **实现**: 可以是直接导入后端服务模块并调用其函数，也可以是基于HTTP/WebSocket的API客户端。

## 5. 集成要点

*   **Python Path**: 确保项目根目录被正确添加到Python路径，以便CLI能够导入 `src` 目录下的后端服务模块。
*   **配置管理**: CLI应能访问和使用 `config.yaml` 中定义的系统配置，例如LLM提供者、API端点等。
*   **异步操作**: 许多后端服务可能涉及异步操作（如LLM调用），CLI命令需要妥善处理异步函数（例如使用 `asyncio.run()`）。

## 6. TDD与可测试性

*   **模块化设计**: 清晰的模块边界和职责分离，便于编写独立的单元测试。
*   **模拟 (Mocking)**: 在测试CLI命令时，可以轻松模拟后端服务的响应，确保测试的独立性和可重复性。
*   **集成测试**: 编写测试用例验证CLI命令与后端服务的集成是否正确。
*   **原子任务**: `UserRequire.md` 中定义的原子任务直接映射到测试用例，确保每个功能点都有对应的测试覆盖。
