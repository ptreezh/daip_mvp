## TDD原则回顾

1. **先写测试**: 在实现任何功能之前，先编写测试用例
2. **红-绿-重构**:
   * 红: 编写一个失败的测试
   * 绿: 编写最少的代码让测试通过
   * 重构: 优化代码结构，保持测试通过
3. **小步快跑**: 每次只实现一个小功能
4. **测试驱动设计**: 通过测试来指导代码设计
