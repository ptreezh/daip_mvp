# Unified Command-Line Interface - 阶段 2: 智能体助手 - 修订版用户故事和应用场景

**文档状态:** 修订版用户故事和应用场景规范
**版本:** 1.1
**日期:** 2025-08-18
**焦点:** 详细描述CLI智能助手的用户故事和应用场景，特别是用户干预和共识追踪功能，根据反馈进行修订。

## 1. 用户角色定义

### 1.1 开发者/高级用户 (Developer/Power User)
* **特征**: 熟悉命令行操作，需要高效完成复杂任务
* **目标**: 快速获取AI助手的帮助，执行复杂任务，监控任务进度
* **技术能力**: 熟悉编程和系统操作

### 1.2 研究人员 (Researcher)
* **特征**: 需要进行深入的分析和研究工作
* **目标**: 利用AI助手进行文献调研、数据分析、观点整理
* **技术能力**: 具备专业领域的知识，可能不熟悉编程

### 1.3 系统管理员 (System Administrator)
* **特征**: 负责系统维护和自动化任务
* **目标**: 通过CLI进行系统监控、配置管理和自动化运维
* **技术能力**: 熟悉系统管理和脚本编写

## 2. 核心用户故事

### 2.1 意图识别与分类

#### 故事1: 开发者寻求技术问题解答
**作为** 一名开发者
**我希望** 向CLI智能助手提问技术问题
**以便** 快速获得解决方案

**场景**:
1. 开发者在终端输入: `daip-cli assistant chat "如何在Python中实现快速排序算法？"`
2. 系统识别这是技术咨询意图
3. 系统启动Secretariat模式，创建任务
4. 系统执行工作流，生成代码示例和解释
5. 系统返回结果给开发者

#### 故事2: 研究人员进行学术探讨
**作为** 一名研究人员
**我希望** 与CLI智能助手讨论学术话题
**以便** 获得多角度的观点和深入分析

**场景**:
1. 研究人员输入: `daip-cli assistant chat "探讨量子计算对未来密码学的影响"`
2. 系统识别这是学术讨论意图
3. 系统启动Forum模式，创建辩论
4. 系统邀请相关领域专家角色参与讨论
5. 系统促进多轮讨论，生成综合观点

### 2.2 入口选择服务

#### 故事3: 系统智能选择最适合的服务入口
**作为** 一名用户
**我希望** 系统能根据我的问题自动选择最合适的服务模式
**以便** 获得最佳的交互体验

**场景**:
1. 用户输入简单问题: `daip-cli assistant chat "今天天气如何？"`
2. 系统分析问题复杂度较低，时间敏感性不高
3. 系统自动选择Secretariat模式快速回答
4. 用户输入复杂问题: `daip-cli assistant chat "分析人工智能在医疗诊断中的应用前景和挑战"`
5. 系统分析问题复杂度高，需要深入探讨
6. 系统自动选择Forum模式进行多角色讨论

### 2.3 工作流编排器

#### 故事4: 开发者执行复杂任务
**作为** 一名开发者
**我希望** 通过CLI助手执行复杂的编程任务
**以便** 自动化完成繁琐的工作

**场景**:
1. 开发者输入: `daip-cli assistant chat "帮我创建一个基于FastAPI的用户管理系统，包含注册、登录和权限控制功能"`
2. 系统识别为复杂任务请求
3. 系统规划工作流: 需求分析 -> 架构设计 -> 代码生成 -> 测试用例生成 -> 文档编写
4. 系统启动工作流执行
5. 系统逐步完成各步骤并向用户报告进度
6. 系统最终交付完整的项目代码和文档

### 2.4 用户干预服务

#### 故事5: 研究人员在讨论中提供专业见解
**作为** 一名研究人员
**我希望** 在AI角色讨论过程中提供我的专业见解
**以便** 引导讨论方向，确保讨论质量

**场景**:
1. 研究人员启动学术讨论: `daip-cli assistant chat "探讨量子计算对未来密码学的影响"`
2. 系统创建Forum会话，多个AI专家角色开始讨论
3. 研究人员查看讨论进展后，认为需要补充一个重要观点
4. 研究人员输入干预: `daip-cli assist intv --content "请考虑量子计算对对称加密算法的影响，这与非对称加密有所不同"`
5. 系统优化用户输入，使其更建设性
6. 系统将干预集成到讨论中
7. AI角色基于用户干预调整讨论方向，提供更全面的分析

#### 故事6: 开发者纠正AI助手的错误理解
**作为** 一名开发者
**我希望** 在AI助手执行任务过程中纠正其错误理解
**以便** 确保最终结果符合我的真实需求

**场景**:
1. 开发者请求创建用户管理系统
2. 系统开始执行工作流，在需求分析阶段误解了权限控制的要求
3. 开发者发现误解后进行干预: `daip-cli assist intv --content "权限控制应该基于RBAC模型，而不是简单的角色分类"`
4. 系统分析干预影响，生成集成建议
5. 系统调整后续工作流步骤，按正确的权限模型实现功能

### 2.5 共识跟踪服务

#### 故事7: 决策者查看AI讨论的共识水平
**作为** 一名决策者
**我希望** 了解AI角色在特定议题上的共识水平
**以便** 做出更明智的决策

**场景**:
1. 决策者启动关于公司技术选型的讨论
2. 多个AI专家角色就不同技术方案进行讨论
3. 决策者随时查看共识状态: `daip-cli assist cons`
4. 系统显示当前共识水平为60%，尚未形成强共识
5. 系统提取关键论点，帮助决策者理解分歧点
6. 讨论继续进行，共识水平提升到85%
7. 系统生成最终的综合观点报告

#### 故事8: 研究人员分析学术讨论的分歧点
**作为** 一名研究人员
**我希望** 识别学术讨论中的主要分歧点
**以便** 深入研究争议话题

**场景**:
1. 研究人员启动关于"人工智能伦理"的学术讨论
2. 不同领域的AI专家角色表达各自观点
3. 研究人员查看分歧分析: `daip-cli assist disag`
4. 系统识别出三个主要分歧点: AI自主权、责任归属、隐私保护
5. 系统为每个分歧点提供支持和反对的论据摘要
6. 研究人员可以针对特定分歧点深入探讨

## 4. 会话管理场景

### 4.1 默认最近会话使用

#### 故事11: 用户使用默认最近会话进行连续交互
**作为** 一名用户
**我希望** 在连续交互时不需要每次都指定会话ID
**以便** 更便捷地与助手交互

**场景**:
1. 用户启动新会话: `daip-cli assistant chat "分析人工智能在医疗诊断中的应用"`
2. 系统创建新会话并设为默认会话
3. 用户进行干预: `daip-cli assist intv --content "请重点关注影像识别技术的应用"`
4. 系统自动使用默认最近会话
5. 用户查看共识: `daip-cli assist cons`
6. 系统自动使用默认最近会话

### 4.2 历史会话选择

#### 故事12: 用户从历史会话中选择特定会话
**作为** 一名用户
**我希望** 能够查看和选择历史会话
**以便** 继续之前的讨论或任务

**场景**:
1. 用户查看历史会话: `daip-cli assist sessions`
2. 系统显示历史会话列表，包含会话ID和主题
   ```
   ID          主题                                     创建时间
   sess_001    分析人工智能在医疗诊断中的应用           2025-08-18 10:30
   sess_002    探讨量子计算对未来密码学的影响           2025-08-18 09:15
   ```
3. 用户选择特定会话: `daip-cli assist session --id sess_002`
4. 系统将会话sess_002设为默认会话
5. 用户进行交互: `daip-cli assist intv --content "请进一步分析量子密钥分发技术"`

### 4.3 智能生成会话主题

#### 故事13: 系统智能生成会话主题
**作为** 一名用户
**我希望** 系统能为我的会话自动生成有意义的主题
**以便** 更容易识别和管理会话

**场景**:
1. 用户启动新会话: `daip-cli assistant chat "我需要一个能够处理用户认证、权限管理和API访问控制的后端服务"`
2. 系统自动分析用户输入，生成会话主题: "后端服务开发：用户认证与权限管理"
3. 系统创建会话并保存主题
4. 用户查看会话列表时能看到清晰的主题描述

## 7. 错误处理和异常场景

### 7.1 用户输入优化场景

#### 故事16: 系统优化不完整的用户请求
**作为** 一名用户
**我希望** 系统能优化我不完整的请求
**以便** 获得更准确的帮助

**场景**:
1. 用户输入模糊请求: `daip-cli assistant chat "帮我做点什么"`
2. 系统识别为不完整请求，优化为: `我认为您可能需要帮助，请您提供更具体的需求描述`
3. 用户补充详细信息后，系统正常处理

### 7.2 系统降级处理场景

#### 故事17: 在服务不可用时提供降级体验
**作为** 一名用户
**我希望** 在部分服务不可用时仍能获得基本帮助
**以便** 不中断我的工作流程

**场景**:
1. 用户请求复杂任务执行
2. 系统检测到部分AI服务不可用
3. 系统降级到基本模式，使用可用服务完成任务
4. 系统告知用户服务降级情况和影响

## 8. 总结

这些修订后的用户故事和应用场景详细描述了CLI智能助手在各种使用情境下的功能表现，特别强调了以下改进点：

1. 移除了团队成员讨论的场景，因为CLI是单用户系统
2. 增加了会话管理的相关场景，包括默认最近会话和历史会话选择
3. 增加了智能生成会话主题的功能描述
4. 增加了精简指令的使用场景
5. 保留并完善了用户干预和共识追踪的核心功能场景
6. 保留了角色提示词和风格定制的场景

通过这些场景，我们可以更好地理解用户需求，确保系统设计能够满足实际使用要求，同时保持系统的简洁性和易用性。
