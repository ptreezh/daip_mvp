# 代码生成质量规则

## 🚨 强制性规则 - 防止语法错误

### 规则1: 文件长度限制
- **单个文件不超过400行**
- **超过400行必须拆分为多个模块**
- **每个类不超过200行**
- **每个方法不超过50行**

### 规则2: 换行符检查 (CRITICAL)
- **每次使用 `fsAppend` 前必须确保内容以正确的换行符开始**
- **类定义前必须有2个空行**
- **方法定义前必须有1个空行**
- **文件末尾必须有1个空行**

#### 强制格式模板:
```python
# fsAppend 内容必须以这种格式开始:
text = """
    def method_name(self):
        \"\"\"方法说明\"\"\"
        pass
        
    def another_method(self):
        \"\"\"另一个方法\"\"\"
        pass


class NewClass:
    \"\"\"新类说明\"\"\"
    
    def __init__(self):
        pass
"""
```

### 规则3: 缩进一致性检查
- **使用4个空格缩进，禁用Tab**
- **每次添加代码前检查上下文缩进级别**
- **类内方法必须缩进4个空格**
- **方法内代码必须缩进8个空格**

### 规则4: 语法验证流程
1. **生成代码前**: 检查上一行的结束符
2. **生成代码中**: 确保每个代码块完整
3. **生成代码后**: 立即进行语法检查

## 🔧 实施策略

### 策略1: 模块化设计
```
大型实现 → 拆分为多个文件:
- core.py (核心类, <200行)
- rules.py (规则类, <200行) 
- utils.py (工具函数, <200行)
- tests.py (测试代码, <300行)
```

### 策略2: 代码生成检查清单
每次生成代码时必须检查:
- [ ] 文件长度是否超过400行
- [ ] 是否需要拆分模块
- [ ] 换行符是否正确
- [ ] 缩进是否一致
- [ ] 语法是否正确

### 策略3: 自动验证
```python
# 每次生成后立即验证
def verify_code_syntax(file_path):
    try:
        with open(file_path, 'r') as f:
            compile(f.read(), file_path, 'exec')
        return True
    except SyntaxError as e:
        print(f"语法错误: {e}")
        return False
```

## 📋 具体执行规则

### 使用 fsWrite 时:
1. 内容必须完整且语法正确
2. 文件长度控制在400行以内
3. 包含完整的类或函数定义

### 使用 fsAppend 时:
1. **开头必须有适当的换行符**
2. **检查与前面代码的连接点**
3. **确保缩进级别正确**
4. **每次追加后验证语法**

### 示例正确格式:
```python
# fsAppend 的正确格式
text = """
    def new_method(self):
        \"\"\"新方法\"\"\"
        return "success"
        
    def another_method(self):
        \"\"\"另一个方法\"\"\"
        pass


class AdditionalClass:
    \"\"\"附加类\"\"\"
    
    def __init__(self):
        self.value = None
"""
```

## 🚫 禁止的做法

1. **禁止**: 直接拼接代码而不检查换行符
2. **禁止**: 单个文件超过500行
3. **禁止**: 不检查语法就提交代码
4. **禁止**: 混合使用空格和Tab缩进

## ✅ 强制执行

- 每次代码生成后立即运行语法检查
- 发现错误立即修复，不允许继续
- 文件过长时强制拆分模块
- 建立代码质量门禁
