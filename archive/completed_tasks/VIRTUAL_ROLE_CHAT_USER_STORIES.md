# 虚拟角色聊天室用户故事文档

## 1. 引言
本文档旨在详细描述虚拟角色聊天室功能的用户故事，以确保开发团队对用户需求有全面且一致的理解。这些用户故事覆盖了从聊天室创建到关闭/删除的整个生命周期，并包含了角色管理、规则设置、文档交互、历史查看等增强功能。

## 2. 用户角色
- **用户 (User)**: 使用CLI与系统交互的人。

## 3. 用户故事

### 故事 1: 启动新的聊天室
**作为** 一个用户,
**我想要** 启动一个新的聊天室，
**以便** 我可以与虚拟角色就特定主题进行讨论。

#### 详细描述
1.  **触发**: 用户输入 `daip-cli chat start [--room <room_name>]` 命令。
2.  **前置条件**: 系统正在运行，用户已通过CLI接入。
3.  **主流程**:
    1.  如果用户未指定 `--room` 参数，系统将自动生成一个临时聊天室名称（如 "ChatRoom-YYYYMMDD-HHMMSS"）。
    2.  如果用户指定了 `--room` 参数，系统将使用用户指定的名称。
    3.  系统提示用户输入聊天主题。
    4.  系统根据主题，使用 `RoleManager` 推荐相关角色。
    5.  系统显示推荐的角色列表。
    6.  用户可以选择：
        *   接受全部推荐角色。
        *   从现有角色库中搜索并选择角色。
        *   创建一个新角色（如果找不到合适的）。
    7.  系统提示用户选择或创建聊天规则（基于制度原语）。
    8.  用户可以选择现有规则或创建新规则。
    9.  系统提示用户是否上传文档作为讨论参考。
    10. 如果用户选择上传，系统提示用户输入文档路径并完成上传。
    11. 系统使用 `ChatCoordinator` 协调 `ChatRoomManager` 创建聊天室。
    12. 系统将新创建的聊天室设置为"当前聊天室"。
    13. 系统输出新聊天室的ID，并提示用户聊天室已创建成功。
4.  **后置条件**: 一个新的聊天室被创建并激活，成为当前聊天室。相关的角色、规则和文档信息被持久化。

### 故事 2: 在聊天室中发送消息
**作为** 一个用户,
**我想要** 向当前或指定的聊天室发送消息，
**以便** 我可以参与到与虚拟角色的讨论中。

#### 详细描述
1.  **触发**: 用户输入 `daip-cli chat message <message>` 或 `daip-cli chat message --room <room_id> <message>`。
2.  **前置条件**: 至少存在一个聊天室。
3.  **主流程 (发送到当前聊天室)**:
    1.  用户输入 `daip-cli chat message <message>`。
    2.  系统识别当前聊天室。
    3.  `ChatCoordinator` 将消息传递给 `ChatSessionService` 添加到当前会话。
    4.  消息被持久化存储。
    5.  系统（通过 `ChatCoordinator`）触发虚拟角色根据上下文生成响应。
    6.  虚拟角色的响应通过 `ChatSessionService` 添加到会话，并显示给用户。
4.  **主流程 (发送到指定聊天室)**:
    1.  用户输入 `daip-cli chat message --room <room_id> <message>`。
    2.  系统识别指定的聊天室。
    3.  如果指定的聊天室不是当前聊天室：
        *   系统提示用户确认是否要切换到指定聊天室。
        *   如果用户确认，原当前聊天室被自动存档（系统可询问是否重命名，回车默认不更改）。
        *   指定的聊天室成为新的当前聊天室。
    4.  继续执行发送消息到当前聊天室的流程。
5.  **后置条件**: 消息和响应被添加到指定聊天室的会话历史中。

### 故事 3: 查看聊天历史
**作为** 一个用户,
**我想要** 查看当前或指定聊天室的历史消息，
**以便** 我可以回顾之前的讨论内容。

#### 详细描述
1.  **触发**: 用户输入 `daip-cli chat history` 或 `daip-cli chat history --room <room_id>`。
2.  **前置条件**: 至少存在一个聊天室。
3.  **主流程 (查看当前聊天室历史)**:
    1.  用户输入 `daip-cli chat history`。
    2.  系统识别当前聊天室。
    3.  `ChatCoordinator` 从 `ChatSessionService` 获取当前聊天室的会话历史。
    4.  系统以清晰的格式（包含时间戳、发送者）显示历史消息。
    5.  （可选）系统支持上滚查看更早的历史信息。
4.  **主流程 (查看指定聊天室历史)**:
    1.  用户输入 `daip-cli chat history --room <room_id>`。
    2.  系统识别指定的聊天室。
    3.  如果指定的聊天室不是当前聊天室：
        *   系统提示用户确认是否要切换到指定聊天室。
        *   如果用户确认，原当前聊天室被自动存档（系统可询问是否重命名，回车默认不更改）。
        *   指定的聊天室成为新的当前聊天室。
    4.  继续执行查看当前聊天室历史的流程。
    5.  系统同时显示该聊天室参与的角色信息。
5.  **后置条件**: 用户成功查看了聊天历史。

### 故事 4: 清除聊天消息
**作为** 一个用户,
**我想要** 清除当前或指定聊天室的消息历史，
**以便** 我可以重新开始一个干净的讨论。

#### 详细描述
1.  **触发**: 用户输入 `daip-cli chat clear` 或 `daip-cli chat clear --room <room_id>`。
2.  **前置条件**: 至少存在一个聊天室。
3.  **主流程**:
    1.  系统识别目标聊天室（当前或指定）。
    2.  系统提示用户确认是否要清除消息历史。
    3.  如果用户确认，`ChatCoordinator` 指示 `ChatSessionService` 清除该聊天室的会话消息。
    4.  系统输出确认信息。
4.  **后置条件**: 目标聊天室的消息历史被清除，但聊天室本身和角色信息等元数据保留。

### 故事 5: 关闭聊天室
**作为** 一个用户,
**我想要** 关闭当前聊天室，
**以便** 我可以结束本次讨论并回到个人助手场景。

#### 详细描述
1.  **触发**: 用户输入 `daip-cli chat close`。
2.  **前置条件**: 存在一个当前聊天室。
3.  **主流程**:
    1.  系统提示用户确认是否要关闭当前聊天室。
    2.  如果用户确认，`ChatCoordinator` 指示 `ChatRoomManager` 将聊天室状态更新为"归档"。
    3.  系统清除"当前聊天室"的设置。
    4.  系统输出确认信息，并提示用户已回到个人助手对话场景。
    5.  用户现在可以通过个人助手进入其他场景（如普通对话、辩论等）。
4.  **后置条件**: 当前聊天室被归档，系统回到个人助手场景。

### 故事 6: 删除聊天室
**作为** 一个用户,
**我想要** 删除一个指定的聊天室，
**以便** 我可以永久移除不需要的聊天记录。

#### 详细描述
1.  **触发**: 用户输入 `daip-cli chat delete <room_id>`。
2.  **前置条件**: 存在ID为 `<room_id>` 的聊天室。
3.  **主流程**:
    1.  系统提示用户确认是否要永久删除ID为 `<room_id>` 的聊天室（包括所有历史消息、角色信息等）。
    2.  如果用户确认，`ChatCoordinator` 指示 `ChatRoomManager` 删除该聊天室及其所有相关数据。
    3.  如果被删除的聊天室是当前聊天室，则清除"当前聊天室"的设置。
    4.  系统输出确认信息。
4.  **后置条件**: 指定的聊天室及其所有数据被永久删除。

### 故事 7: 查看共识和分歧
**作为** 一个用户,
**我想要** 在聊天室中查看当前讨论的共识和分歧，
**以便** 我可以更好地理解讨论的进展和关键争议点。

#### 详细描述
1.  **触发**: 用户在聊天室中输入特定的共识/分歧查看指令（如 `/consensus`, `/disagreement`）。
2.  **前置条件**: 存在一个当前聊天室，且该聊天室中有一定的讨论历史。
3.  **主流程**:
    1.  `ChatCoordinator` 获取当前聊天室的会话历史。
    2.  `ChatCoordinator` 调用已有的智能助手服务（如 `PersonalAssistantRouter` 中的相关方法）分析会话历史。
    3.  系统显示分析得到的共识信息或分歧点。
4.  **后置条件**: 用户成功查看了当前讨论的共识或分歧。

## 4. 非功能性需求
*   **可靠性**: 系统应确保聊天室数据、消息历史和角色信息的持久化存储。
*   **可用性**: 系统应提供清晰的用户提示和错误信息。
*   **性能**: 消息发送和历史查询应在合理时间内完成。
