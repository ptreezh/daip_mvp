# Cline 可用规则：从经验教训中提炼

**日期**: 2025-07-06
**作者**: Cline (AI 协作专家)

## 核心开发与预防准则 (P1 - 必须遵守)

以下是从项目经验教训中提炼出的、Cline 在代码生成、开发、测试和审查过程中必须严格遵循的核心准则，旨在提高效率并确保代码质量：

1.  **需求澄清与接口先行**:
    *   **准则**: 在开始编码前，主动寻求需求细化，明确所有模块接口（包括参数、返回值、异常），并定义数据模型和 API 契约。
    *   **应用**: 优先使用类型注解和 Pydantic 模型定义接口。
    *   **围栏**: 未明确的需求或接口，**绝不** 擅自生成或实现。

2.  **测试驱动与边界覆盖**:
    *   **准则**: 始终先编写测试，再实现代码。测试应全面覆盖正常、异常、边界和时序场景。
    *   **应用**: 异步测试中，明确断言异步函数的调用和状态变化，**避免** 依赖不稳定的 `asyncio.sleep` 进行时序同步。
    *   **围栏**: 核心逻辑和关键接口，**必须** 有配套的测试用例。

3.  **异步依赖显式管理**:
    *   **准则**: 在异步代码中，任何对另一个异步操作结果的依赖都必须通过 `await` 显式管理。
    *   **应用**: 优先使用 `asyncio.gather`, `asyncio.wait`, `asyncio.TaskGroup` 等结构化并发工具来管理并发任务。
    *   **围栏**: **禁止** 隐式时序依赖，**禁止** 仅依赖 `sleep` 进行异步同步。

4.  **防御性编程与健壮错误处理**:
    *   **准则**: 永远假设外部输入（来自用户、API、LLM）可能是不完美的。在代码中加入严格的输入验证和全面的错误处理。
    *   **应用**: 捕获特定、可预期的异常（如 `json.JSONDecodeError`, `TypeError`），**避免** 使用过于宽泛的 `except Exception`。详细记录错误日志，并为每个组件定义明确的失败策略。
    *   **围栏**: 任何外部输入处理，**必须** 包含验证和异常捕获。

5.  **代码变更同步测试**:
    *   **准则**: 任何代码重构或接口变更，都必须伴随所有相关测试用例的相应更新。
    *   **应用**: 在修改代码的同时，同步更新测试用例的参数、断言和调用方式。
    *   **围栏**: 代码变更后，**必须** 确保受影响的测试通过，否则 **禁止** 合并。

6.  **深入理解外部依赖与模拟**:
    *   **准则**: 在与外部服务（如 LLM、分词器）或复杂组件集成时，投入时间充分了解其 API、行为和局限性。
    *   **应用**: 在测试中，使用 Mock / Stub / Fake 对象精确模拟外部依赖的行为，覆盖成功、失败和不同格式的场景。
    *   **围栏**: **禁止** 在未充分理解外部依赖行为的情况下进行集成或测试。

7.  **代码生成器辅助，人工审查核心**:
    *   **准则**: 代码生成器可提供良好结构和基础代码，但复杂的业务逻辑、异步交互和异常处理，**必须** 经过人类开发者深入理解和细致审查。
    *   **应用**: 对生成代码的异步、I/O、并发和安全敏感部分进行重点审查。
    *   **围栏**: AI 生成的核心业务逻辑和安全敏感代码，**强制** 人工审核。
