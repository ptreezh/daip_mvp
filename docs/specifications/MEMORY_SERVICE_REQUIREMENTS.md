# 内存服务需求文档 (单机版)

## 1. 功能概述

内存服务模块是AI实现连贯思考和长期记忆的核心。它通过一个**三层记忆架构**，并与知识模块紧密协同，为LLM的每一次思考构建最有效、最全面的上下文信息。

## 2. 三层记忆架构 (Three-Layer Memory Architecture)

### 2.1 第一层：短期记忆 (Short-Term Memory)
- **载体**: 纯内存中的Python对象，与当前会话绑定。
- **内容**: 当前会话的完整、实时的交互历史（用户输入、AI回复、工具调用及输出）。
- **特性**: 读写速度最快（毫秒级），但在会话结束后销毁。用于支撑连续的多轮对话。

### 2.2 第二层：中期记忆 (Mid-Term Memory)
- **载体**: 存储在本地SQLite数据库中的、经过处理的结构化文本。
- **内容**: 当短期记忆（对话历史）变得过长时，系统会调用LLM，将其**结构化地压缩**成“中期记忆”。
- **触发机制**: 当短期记忆的Token占用率超过一个可配置的阈值（如 **90%**）时，自动触发压缩。
- **压缩算法**: 采用类似Claude的“**8段式结构化压缩**”思想。即，使用一个特定的Prompt模板，指令LLM将对话历史提炼成包含“背景上下文”、“关键决策”、“用户意图演进”、“未解决问题”等多个固定方面的结构化摘要。这比简单的流水账摘要能更好地保留关键信息。
- **存储**: 中期记忆将作为 `Session` 对象的一个字段 `compressed_history` 存储在数据库中。
- **存储**: 压缩后的中期记忆将存储在 `Session` 对象的 `compressed_history` 字段中，并持久化到数据库。

### 2.3 第三层：长期记忆 (Long-Term Memory)
- **载体**: 本地文件（如 `project_context.md`）或SQLite数据库中的特定表格。
- **内容**: 跨会话的、高度概括的全局信息。例如：项目总体目标、用户的主要偏好、代码风格规范等。
- **更新机制**: 可由用户手动编辑，或在项目结束时由AI生成最终总结并存入。

## 3. 上下文构建与管理策略

在每次调用LLM前，内存服务必须执行以下上下文构建流程：

1.  **信息源优先级**: 按以下顺序组合信息：
    1.  **系统指令**: AI角色的核心指令。
    2.  **长期记忆**: `project_context.md`中的全局信息。
    3.  **用户最新问题**: 当前的用户输入。
    4.  **相关外部知识**: 从知识库中检索到的信息片段。
    5.  **相关中期记忆**: 从数据库中检索到的、与当前主题相关的历史会话结构化摘要。
    6.  **短期记忆**: 最近的N轮对话历史。

2.  **上下文裁剪策略**: 当信息总量超长时，按以下策略裁剪：
    *   为“外部知识”和“中期/长期记忆”分配固定的Token预算。
    *   对“短期记忆”（对话历史）部分进行滑动窗口压缩，优先保留最新的对话。

3.  **透明化**: 上下文的最终Token用量必须在UI/TUI上对用户可见。

## 4. 非功能需求

- **性能**: 短期记忆访问为纯内存操作，速度极快。中期和长期记忆的数据库写入应避免阻塞主流程。
- **可靠性**: 对数据库的写入必须是事务性的，防止数据损坏。应用关闭时应有优雅的保存机制。
- **安全性**: 所有记忆数据均存储在用户本地，由用户物理保管。

## 5. API 规范 (API Specification)

`MemoryService` 类应提供以下方法：

- `get_long_term_memory() -> str`:
  - **功能**: 从长期记忆存储（如 `project_context.md`）中检索内容。
  - **返回**: 字符串形式的长期记忆内容。

- `compress_history(session: Session) -> None`:
  - **功能**: 根据中期记忆策略，压缩会话历史。
  - **返回**: 无。

- `construct_prompt(goal: str, last_tool_result: Optional[str], last_llm_response: Optional[str], session: Session) -> str`:
  - **功能**: 根据三层记忆架构和上下文构建策略，为LLM构建最终的Prompt。
  - **返回**: 字符串形式的Prompt。

- `get_todo_list() -> List[TodoItem]`:
  - **功能**: 从内存中检索当前的待办事项列表。
  - **返回**: `TodoItem` 对象列表。

- `is_todo_list_complete() -> bool`:
  - **功能**: 检查待办事项列表中的所有任务是否都已完成。
  - **返回**: 如果所有任务都已完成，则返回 `True`，否则返回 `False`。
