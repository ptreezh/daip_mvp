# 知识管理需求文档 (单机版)

## 1. 功能概述

知识管理模块是DAIP-LIVE（单机版）的智慧核心。它负责将用户指定的**本地文件夹**中的文档进行处理、向量化，并构建一个支持高效语义检索的本地知识库。

## 2. 核心功能

### 2.1 知识源与处理
- **本地文件夹作为源**: 用户可以在配置中指定一个或多个本地文件夹作为知识库的来源。
- **自动化处理**: 系统应能自动或手动触发对源文件夹的扫描，识别新增、修改或删除的文档。
- **多格式支持**: 必须支持常见的文档格式，如 Markdown (.md), 纯文本 (.txt)，并可选支持 PDF, Word等。
- **变更检测**: 通过比对文件的哈希值（hash），高效检测已变更的文档，仅对变更部分进行重新处理。

### 2.2 嵌入模型管理 (Embedding Model Management)
- **模型可配置**: **必须允许用户在 `config.yaml` 中配置用于文档向量化的嵌入模型**。这使用户能根据自己的硬件和需求，在不同的本地或云端嵌入模型之间进行选择。
- **默认模型**: 系统必须提供一个开箱即用的、性能良好的默认本地嵌入模型。
- **接口统一**: 调用不同的嵌入模型应通过`ModelProvider`模块的统一`embed(text)`接口完成。

### 2.3 知识存储
- **嵌入式向量存储**: 文档被切块和向量化后，向量数据必须存储在**嵌入式向量数据库**（如FAISS索引文件或ChromaDB的本地目录）中。
- **元数据存储 (SQLite)**: 每个被处理的文档及其切块（chunk）的元数据（如文件路径、标题、标签、文件哈希值）必须存储在本地SQLite数据库中，与向量数据关联。

### 2.4 智能检索
- **语义相似度搜索**: 必须提供一个核心的`search(query_text)`函数，该函数能将输入文本向量化，并在向量数据库中进行高效的相似度搜索，返回最相关的文档块内容。
- **元数据过滤**: 搜索功能应支持基于元数据（如文件名、标签）的预过滤，以缩小检索范围，提高查询精度。

### 2.5 元数据与实体提取
- **标签提取**: 在文档处理过程中，可调用LLM自动为文档内容提取关键词或实体，作为标签存入SQLite元数据中。
- **关系追踪**: 新增`document_relations`表存储跨文档语义关联（如引用关系、概念继承），支持深度推理场景。关系数据通过LLM分析文档内容自动生成，包含置信度评分。

## 3. 非功能需求

### 3.1 性能要求
- **索引性能**: 对一个中等大小（如100MB）的文本文档库进行首次完整索引的时间应在可接受范围内（例如，数分钟内，具体取决于硬件）。
- **检索性能**: 单次语义检索的响应时间应在1秒以内。

### 3.2 可靠性
- **数据一致性**: 对SQLite元数据的写入必须是事务性的。向量索引文件的写入操作必须是安全的，避免因中断而损坏整个索引。
- **错误处理**: 当处理不受支持的文件格式或加密文档时，系统应能跳过该文件并记录错误日志，而不是中断整个索引过程。

### 3.3 可管理性与用户体验
- **CLI控制**: 提供`daip knowledge sync`等CLI命令，用于手动触发对知识库的完全同步或增量同步。
- **增强的UI交互**: 本地Web UI界面必须提供一个专门的“知识库管理”页面，功能包括：
  - **状态可视化**: 清晰地展示知识库的统计信息，如已索引的文件数量、来源文件夹路径、上次同步时间等。
  - **文件列表**: 显示所有已被检测到的源文件及其索引状态（已索引、待处理、失败）。
  - **手动控制**: 提供“立即同步”按钮。
  - **上传文件 (可选)**: 支持用户直接通过UI界面上传文档到知识库源文件夹。
  - **删除索引**: 支持用户从索引中移除某个文件或整个知识库。
