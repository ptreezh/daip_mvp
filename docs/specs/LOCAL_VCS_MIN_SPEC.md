# 本地最小化版本管理规范（隐式，无远端）

目标
- 为个人版提供“无感知”的本地版本管理与快照，便于回滚与历史追溯，不暴露 Git 概念

方案（KISS）
- 在项目根 .daip_vcs/ 建立本地版本存储（首选基于 git 本地仓；若 git 不可用，退化为快照目录+压缩包）
- 追踪范围（默认）：wiki/**, roles/**, workflows/**, docs/**（可配置白/黑名单）

触发与提交策略
- 触发点：
  - 每次成功写文件操作（聚合：N秒内批量为一次提交，默认60s）
  - 会话结束时（TUI退出或debate完成）
  - 每日一次定时提交（0点后首次启动）
- 提交信息：时间戳+变更摘要（新增/修改/删除计数）
- 标签：每日首个提交打 tag YYYY-MM-DD

容量与清理（每日/每周自动）
- 目标上限：默认 500MB；超过触发 LRU 清理（最旧commit/快照优先）
- 每周：压缩老历史（仅保留每日首个提交的快照），最近7天保留完整历史

依赖自检与降级
- 启动时检查 git；不可用则使用“快照模式”（复制变化文件到 .daip_vcs/snapshots/ts/ 并压缩）

安全与隐私
- 仅本地；不与远端联动；不记录敏感密钥文件（.env 等）

TDD 要点
- 触发策略测试（聚合/会话结束/每日）
- 配额与LRU清理测试；周清理策略测试
- 降级路径测试（无 git 场景）

完成标准
- 默认启用、零感知；能够回看最近版本并回滚单文件
- 仓库不膨胀（阈值+清理有效）
