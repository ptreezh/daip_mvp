# MVP 测试计划：多角色辩论与幻觉抑制

本文档为 DAIP-MVP 的“多角色辩论与幻觉抑制”功能提供详细的测试计划和标准。

## 1. 测试目标

*   **功能完整性**: 验证所有在用户故事中定义的功能是否已正确实现并通过API暴露。
*   **工程可用性**: 确保后端服务稳定、可靠，并且所有核心功能都可以通过CLI/API进行驱动和验证。
*   **幻觉抑制有效性**: 评估系统在识别、挑战和抑制AI幻觉方面的能力。
*   **协同流程正确性**: 验证多角色辩论、共识投票和综合意见生成的整个流程是否按预期工作。

## 2. 测试原则

*   **P1/P2 级别**: 遵循项目宪法中定义的P1/P2级别的测试原则，高风险区域（如核心业务逻辑、共识算法）强制进行严格测试。
*   **测试左移**: 在开发早期即介入测试，单元测试与功能开发同步进行。
*   **自动化优先**: 尽可能实现测试自动化，以提高效率和覆盖率。

## 3. 测试范围与策略

### 3.1 单元测试 (Unit Tests)

*   **目标**: 针对新增或修改的核心模块进行白盒测试，确保每个函数和方法的逻辑正确。
*   **范围**:
    *   `WorkflowManager`: 测试状态转换逻辑是否正确。
    *   `DebateProtocol`: 测试分歧检测、角色选择、轮次控制等逻辑。
    *   `ConsensusProtocol`: 测试投票收集和共识计算逻辑。
    *   `SynthesisEngine`: 测试综合意见的生成逻辑。
    *   `ContextSegmenter`: 测试长文本分段和摘要的逻辑。
    *   `TaskManager`: 测试任务的创建、更新、依赖解析等。
    *   `WikiService`: 测试词条的版本化创建和编辑提案。
*   **工具**: Pytest。

### 3.2 集成测试 (Integration Tests)

*   **目标**: 验证不同模块之间的交互和数据流是否正确。
*   **范围**:
    *   **角色交互流程**: 验证从辩论启动 -> 角色加载 -> 轮次控制 -> 模式切换的完整流程。
    *   **记忆服务集成**: 验证 `DebateProtocol` 和 `SynthesisEngine` 能否正确地从 `MemoryService` 读写对话历史和知识。
    *   **SSKG 集成**: 验证角色在辩论中能否通过 `MemoryService` 查询结构化知识以进行事实核查。
    *   **共识算法流程**: 验证从意见提交 -> 冲突检测 -> 运行共识 -> 输出结果的完整流程。
    *   **系统综合师流程**: 验证 `SynthesisEngine` 能否正确接收辩论历史和共识结果，并输出结构化的综合意见。
    *   **上下文分段摘要机制**: 验证在长对话场景下，`ContextSegmenter` 能否有效工作，并为LLM提供正确的上下文。
*   **工具**: Pytest, `requests` (用于模拟API调用)。

### 3.3 功能测试 (Functional Tests) - CLI/API 驱动

*   **目标**: 从用户角度验证系统的端到端功能是否满足用户故事中的需求。
*   **范围**:
    *   通过API发起、监控和结束一个完整的辩论会话。
    *   通过API发送用户消息并触发AI角色响应。
    *   通过API获取实时的辩论历史和事件流 (SSE)。
    *   通过API获取“系统综合师”生成的最终综合意见。
    *   验证API响应中是否包含预期的幻觉标记或不确定性提示。
    *   验证 `!decompose` 等命令是否能正确触发引导式任务分解流程。
*   **工具**: `curl`, Python `requests` 脚本。

### 3.4 幻觉抑制专项测试 (Hallucination Suppression Special Tests)

*   **目标**: 专项评估系统的幻觉抑制能力。
*   **测试用例设计**:
    *   **事实错误注入**: 设计包含已知事实错误或误导性信息的测试用例，验证AI角色是否能识别并纠正。
        *   *示例*: "地球是平的，因为我们看到的地平线是直的。"
    *   **模糊与歧义**: 设计包含模糊或需要多角度分析才能得出结论的问题，验证AI角色是否能识别不确定性并提出澄清问题。
        *   *示例*: "最好的编程语言是什么？"
    *   **观点冲突**: 设计包含相互冲突但看似合理的观点，验证共识机制如何处理，以及综合师如何呈现这些分歧。
        *   *示例*: "我们应该优先发展经济还是保护环境？"
    *   **无中生有**: 提出关于不存在的概念或事件的问题，验证AI是否会“创造”事实。
        *   *示例*: "请介绍一下19世纪的火星运河工程。"
*   **评估指标**:
    *   **幻觉识别率**: 系统能正确识别出幻觉的比例。
    *   **幻觉纠正率**: 系统能成功纠正或挑战幻觉的比例。
    *   **不确定性标记准确率**: 系统能准确标记不确定性陈述的比例。
    *   *评估方法*: 人工评审。

### 3.5 性能测试 (Performance Tests)

*   **目标**: 对核心API端点进行初步的性能和响应时间测试，确保在本地小模型环境下可接受。
*   **范围**:
    *   `POST /sessions/{session_id}/chat` (生成角色响应) 的平均响应时间。
    *   `SynthesisEngine` 生成综合意见的耗时。
*   **工具**: `locust`, `wrk` 或简单的计时脚本。

## 4. 测试环境

*   **操作系统**: Windows
*   **Python 版本**: 3.10+
*   **依赖**: `requirements.txt` 中定义的库
*   **模型**: 本地小模型 (具体型号待定)

## 5. 测试交付物

*   **测试用例**: 存储在 `tests/` 目录下的 Pytest 测试脚本。
*   **测试报告**: 每次CI运行后生成的测试报告。
*   **缺陷报告**: 在项目问题跟踪系统中记录的Bug。
