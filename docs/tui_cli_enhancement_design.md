# TUI CLI功能增强设计方案

## 1. 功能需求分析

根据用户提出的需求，TUI CLI需要支持以下快捷命令：

### 1.1 个人助手相关命令
- `/pa <goal>` - 个人助手，执行指定目标

### 1.2 角色管理相关命令
- `/role add <name> <persona>` - 添加角色
- `/role view <name>` - 查看角色详情
- `/role list` - 列出所有角色

### 1.3 知识库相关命令
- `/0 [query]` - 搜索知识库，无参数时同步知识库

### 1.4 辩论系统相关命令
- `/debate <topic> [--roles <roles>] [--rounds <num>]` - 启动辩论

### 1.5 会话管理相关命令
- `/v [query]` - 搜索会话历史
- `/l` - 列出会话历史
- `/c` - 中止当前会话，回到上级会话
- `ESC` - 中止所有会话，回到默认初始会话
- `/g` - 继续当前会话
- `/p` - 暂停当前会话
- `/t` - 列出会话树
- `/tc <session_id>` - 中止当前会话并跳转到指定会话
- `/tt <session_id>` - 暂停当前会话并跳转到指定会话

## 2. 现有TUI实现分析

当前TUI实现已具备以下基础功能：
1. 基本的Textual应用框架
2. 消息显示区域（log_view）
3. 用户输入框（user_input）
4. 快捷命令处理框架（_handle_shortcut_command方法）
5. 事件处理机制（post_event方法）

但还缺少以下功能：
1. 会话管理功能
2. 完整的角色管理命令
3. 完善的会话树显示和导航
4. 会话状态控制（暂停、继续、中止等）

## 3. 设计方案

### 3.1 架构设计

我们将采用以下架构设计：

1. **命令解析层**：在TUI中增加一个命令解析器，负责解析用户输入的快捷命令
2. **会话管理层**：增加会话管理功能，支持会话树、会话状态控制等
3. **命令执行层**：将解析后的命令转换为对底层服务的调用
4. **UI更新层**：根据命令执行结果更新UI显示

### 3.2 核心组件设计

#### 3.2.1 SessionManager扩展
需要扩展会话管理器以支持：
- 会话树结构管理
- 会话状态控制（运行、暂停、中止）
- 会话导航功能

#### 3.2.2 TUI命令处理器
在现有TUI基础上增加：
- 完整的快捷命令解析和执行逻辑
- 会话状态显示和控制
- 会话树显示功能

#### 3.2.3 RoleManager集成
集成角色管理功能：
- 角色添加、查看、列表功能
- 与现有角色管理器的集成

### 3.3 详细设计

#### 3.3.1 快捷命令处理流程
1. 用户在输入框输入以`/`开头的命令
2. TUI捕获输入并调用命令解析器
3. 命令解析器识别命令类型并解析参数
4. 调用相应的命令处理器执行命令
5. 更新UI显示命令执行结果

#### 3.3.2 会话管理增强
1. 实现会话树结构，支持父子会话关系
2. 实现会话状态管理（运行、暂停、中止）
3. 实现会话导航功能，支持按ID跳转

#### 3.3.3 UI增强
1. 增加会话状态显示
2. 增加会话树显示功能
3. 增加命令执行结果提示

## 7. 风险和缓解措施

### 7.1 技术风险
1. **会话状态同步问题**：确保会话状态在TUI和后端之间正确同步
   - 缓解措施：实现状态变更事件机制

2. **命令执行阻塞UI**：长时间运行的命令可能阻塞UI
   - 缓解措施：使用异步执行和进度提示

### 7.2 设计风险
1. **命令冲突**：新命令可能与现有功能冲突
   - 缓解措施：进行充分的命令冲突检查

2. **UI复杂度增加**：功能增加可能导致UI复杂度上升
   - 缓解措施：采用模块化设计，保持UI简洁
