# TUI/CLI 规范文档 (符合BMAD方法和Kiro规范)

## 1. 概述

本文档定义了DAIP-LIVE系统的TUI/CLI交互规范，遵循BMAD方法和Kiro规范的核心理念，结合TDD驱动开发原则以及KISS、YAGNI、SOLID设计原则。

## 2. 设计原则

### 2.1 BMAD方法和Kiro规范对齐
- **AI即团队**: TUI/CLI作为用户与AI团队交互的接口，提供清晰的命令结构和反馈机制
- **规范驱动**: 所有命令和交互都遵循明确的规范定义
- **意图驱动**: 用户输入被准确解析并转化为系统可执行的指令

### 2.2 TDD驱动开发原则
- **测试先行**: 在实现功能前先编写测试用例
- **红绿重构**: 遵循测试驱动开发的红绿重构循环
- **简洁设计**: 仅实现通过测试所需的最小功能

### 2.3 KISS原则 (Keep It Simple, Stupid)
- 命令结构简单直观
- 交互流程清晰明了
- 避免不必要的复杂性

### 2.4 YAGNI原则 (You Aren't Gonna Need It)
- 仅实现当前需要的功能
- 避免过度设计和预置功能
- 保持代码库精简

### 2.5 SOLID原则
- **单一职责**: 每个命令和模块只负责一个功能
- **开闭原则**: 系统对扩展开放，对修改封闭
- **依赖倒置**: 高层模块不依赖低层模块的具体实现

## 3. CLI命令规范

### 3.1 命令结构
```
daip <command> [subcommand] [options] [arguments]
```

### 3.2 核心命令

#### 3.2.1 个人助手命令
```
daip pa "<任务描述>"
```
- 功能: 启动个人助手执行指定任务
- 参数: 任务描述文本
- 快捷方式: `/pa <任务描述>`

#### 3.2.2 角色管理命令
```
daip role list                    # 列出所有角色
daip role view <角色名>           # 查看角色详情
daip role add <角色名> <描述>     # 添加新角色 (待实现)
```
- 快捷方式: 
  - `/role list`
  - `/role view <角色名>`
  - `/role add <角色名> <描述>`

#### 3.2.3 知识库操作命令
```
daip knowledge sync               # 同步知识库
daip knowledge search "<查询>"    # 搜索知识库 (待实现)
```
- 快捷方式:
  - `/0` (同步知识库)
  - `/0 <查询>` (搜索知识库)

#### 3.2.4 辩论系统命令
```
daip debate start "<主题>" [--roles "<角色1,角色2>"] [--rounds <轮数>]
```
- 快捷方式: `/debate <主题> [角色1,角色2]`

#### 3.2.5 会话管理命令
```
daip session list                 # 列出历史会话
daip session view <会话ID>        # 查看会话详情
```
- 快捷方式: `/v [查询关键词]` (搜索会话历史)

### 3.3 命令设计规范

#### 3.3.1 命令命名规范
- 使用动词开头，如 `run`, `sync`, `list`
- 子命令使用名词，如 `session`, `role`
- 保持命令简短但语义明确

#### 3.3.2 参数规范
- 必需参数使用尖括号 `<参数名>`
- 可选参数使用方括号 `[参数名]`
- 选项参数使用双横线 `--选项名`

#### 3.3.3 输出规范
- 成功操作使用绿色输出
- 警告信息使用黄色输出
- 错误信息使用红色输出
- 表格数据使用统一的表格格式

### 4.2 交互流程

#### 4.2.1 命令输入
- 用户在底部输入框输入命令
- 支持快捷命令 (以/开头)
- 支持普通文本输入

#### 4.2.2 命令处理
- 解析用户输入
- 识别是否为快捷命令
- 执行相应功能
- 显示结果

#### 4.2.3 状态显示
- 实时显示当前模型信息
- 显示Token使用情况
- 显示系统状态 (思考中、执行工具等)

### 4.3 内容渲染规范

#### 4.3.1 Agent思考/计划
- 使用斜体显示
- 特定颜色标识 (如蓝色)

#### 4.3.2 工具调用
- 带边框的高亮区块
- 显示工具名和参数

#### 4.3.3 工具输出
- 带边框的区块
- 成功/失败状态标识
- 语法高亮显示代码和JSON
- 长内容支持滚动

#### 4.3.4 LLM回复
- 流式"打字机"效果显示
- 支持Markdown渲染

### 4.4 TUI启动行为

#### 4.4.1 冷启动 (Cold Start)
- **定义**: 首次启动应用，或启动时未加载任何特定历史会话。
- **行为**:
  - **状态栏**: 应显示欢迎信息或就绪状态，例如 `欢迎使用 DAIP-LIVE！| Ready`。不应显示任何与任务执行相关的状态（如“已完成”）。
  - **主内容区**: 应显示简短的欢迎信息和核心命令入门指南，引导用户开始操作。
  - **Token计数**: Token使用量应明确显示为 `0`。

#### 4.4.2 会话加载 (Session Load)
- **定义**: 启动时指定或自动加载一个之前的会话。
- **行为**:
  - **状态栏**: 应显示被加载会话的最终状态（如 `已完成`, `已停止` 等），并包含会话ID或名称以提供上下文。
  - **主内容区**: 应完整渲染被加载会话的所有历史记录。
  - **Token计数**: 应显示该会话的总Token消耗量。

### 4.5 命令自动补全 (Command Auto-completion)

- **触发条件**: 当用户在输入框中输入 `/` 字符时，自动触发补全建议。
- **UI表现**: 在输入框正上方显示一个浮动列表框，展示所有可用的快捷命令。
- **内容显示**: 每行显示一个命令及其简短说明，例如：`/pa <goal> - 启动个人助手`。
- **动态过滤**: 当用户在 `/` 后继续输入字符时，建议列表应根据已输入内容进行实时过滤。
- **交互逻辑**:
  - 用户可使用 `上/下箭头` 键在建议列表中导航。
  - 按 `Tab` 键或 `Enter` 键可将当前高亮的命令补全至输入框，并允许用户继续输入参数。
  - 按 `Esc` 键或在列表外单击可关闭建议列表。

## 5. 快捷命令规范

### 5.1 快捷命令格式
所有快捷命令以"/"开头，格式为:
```
/<命令> [参数]
```

### 5.2 快捷命令映射
| 快捷命令 | 对应完整命令 | 功能 |
|---------|-------------|------|
| /pa | daip pa | 个人助手 |
| /role | daip role | 角色管理 |
| /0 | daip knowledge | 知识库操作 |
| /debate | daip debate start | 启动辩论 |
| /v | daip session | 会话管理 |

## 6. 错误处理规范

### 6.1 错误分类
- 命令解析错误
- 参数验证错误
- 执行错误
- 系统错误

### 6.2 错误响应
- 提供清晰的错误信息
- 指出错误原因
- 给出解决建议
- 使用红色高亮显示

## 7. 测试规范

### 7.1 单元测试
- 每个命令功能都有对应的单元测试
- 测试命令解析和执行逻辑
- 验证输出格式和内容

### 7.2 集成测试
- 测试命令间的交互
- 验证TUI/CLI整体流程
- 模拟用户输入和系统响应

### 7.3 测试驱动开发流程
1. 编写测试用例 (红)
2. 实现最小功能通过测试 (绿)
3. 重构代码优化结构 (重构)
4. 重复上述过程
