### 任务：修复 `test_token_usage_is_accumulated` 测试失败问题

**问题描述**：
- `tests/agent_engine/test_workflow.py` 中的 `test_token_usage_is_accumulated` 测试持续失败
- 预期行为：Agent 在一个执行步骤中完成"思考 -> 使用工具 -> 再次思考 -> 最终响应"的完整序列，调用两次大模型（`generate` 函数）
- 实际行为：测试结果始终是 `AssertionError: assert 100 == 200`，证明 `generate` 函数只被调用了一次

**TDD驱动解决方案**：

#### 阶段一：原子单元测试 - `_parse_tool_call` 方法 ✅
- **目标**：彻底、绝对地确认 `_parse_tool_call` 函数的行为
- **实施**：
  1. 创建全新的测试文件 `tests/agent_engine/test_isolated_step_executor.py`
  2. 编写同步的、不依赖任何 fixture 的测试函数 `test_isolated_step_executor_loop`
  3. 直接用字符串 `"Use Tool: search_web(query='test')"` 调用 `StepExecutor._parse_tool_call`
  4. 断言其返回值等于 `('search_web', {'query': 'test'})`
- **结果**：测试通过 ✅，确认 `_parse_tool_call` 方法工作正常

#### 阶段二：隔离集成测试 - `StepExecutor` 状态机 ✅
- **目标**：在完全隔离的环境中，验证 `StepExecutor` 的内部循环
- **实施**：
  1. 创建隔离测试 `test_isolated_step_executor_loop`
  2. 不使用 `AgentExecutor`，直接实例化 `StepExecutor`
  3. 为所有依赖提供干净的 `AsyncMock`
  4. 精确设置 `model_provider.generate` 的 `side_effect`
  5. 调用 `async for event in step_executor.execute_step(...)` 并收集事件
  6. 断言 `model_provider.generate.call_count == 2`
- **关键发现**：测试失败，输出显示 `"Tool 'search_web' not available. Ignored."`

#### 阶段三：根因定位与修复 ✅
- **根因分析**：
  - 在 `StepExecutor.step_executor.py:168` 中，代码检查工具是否可用：
    ```python
    has_tool = hasattr(self.tool_manager, "_registry") and name in getattr(self.tool_manager, "_registry", {})
    ```
  - 原始测试的 `mock_services` fixture 中的 `tool_manager` 没有 `_registry` 属性
  - 导致工具调用被认为是"不可用"，状态机直接跳转到 `RESPONDING` 状态
  - 跳过了 `EXECUTING_TOOL` 状态，因此没有第二次 `generate` 调用

- **修复方案**：
  - 在 `tests/agent_engine/test_workflow.py` 的 `mock_services` fixture 中添加正确的工具注册表模拟：
    ```python
    tool_manager = AsyncMock()
    tool_manager._registry = {
        "search_web": MagicMock(),
        "ToolA": MagicMock(),
        "ToolB": MagicMock()
    }  # Mock the tool registry with all needed tools
    ```

- **修复结果**：
  - ✅ `test_token_usage_is_accumulated` 现在通过（100 → 200 tokens）
  - ✅ `test_tool_execution_flow` 正常工作
  - ✅ `test_reflection_loop_flow` 正常工作
  - ✅ 状态机正确执行：`THINKING → EVALUATING → EXECUTING_TOOL → THINKING → EVALUATING → RESPONDING`
