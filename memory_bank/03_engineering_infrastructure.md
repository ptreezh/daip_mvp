# 工程卓越与AI基础架构

**核心思想：** 将项目的物理和逻辑结构转化为AI可以理解和利用的上下文，确保AI的产出与项目的实际环境和约束高度对齐，消除因信息不对称导致的错误和冗余。

### 1. 项目结构与环境约定
*   **标准化项目目录框架：** 采用统一、清晰、分层的项目目录结构。
*   **路径约定与引用规范：** 定义清晰的路径引用规范。
*   **环境管理与虚拟环境：** 所有开发和测试环境必须使用虚拟环境。

### 2. 真实接口与服务依赖
*   **与真实系统接口对齐：** 所有由AI生成的测试代码，其调用的系统功能接口必须与当前真实系统中的代码接口**完全对齐**。
*   **服务依赖与状态检测：** 在进行集成测试或端到端测试前，必须检测所有前置依赖服务是否正常启动并可用。

### 3. Cursor Rules: 自动化、上下文感知的AI行为指导
*   **概念：** 在项目层面定义AI行为的规则集，自动注入到AI的Prompt中，并可根据文件路径、类型进行上下文匹配。
*   **实践：**
    *   **告别手动复制粘贴：** 完全替代手动注入系统指令。
    *   **上下文感知规则：** 为不同类型的文件（如生产代码、测试文件）定义不同规则。
    *   **强制执行标准：** 这是在AI生成阶段最直接、最自动化的P0/P1规则强制执行方式。

### 4. Cursor Memory Bank: 深度项目上下文的AI知识库
*   **概念：** 将项目中的重要文档、设计决策、复杂模块解释等“非代码”信息添加到AI的记忆中。
*   **实践：**
    *   **消除“幻觉”：** 提供权威、项目特定的知识。
    *   **加速新成员上手：** 新成员可通过AI快速理解项目设计理念。
    *   **保持一致性：** 确保AI生成代码符合项目的历史决策。

### 5. CI/CD Pipeline与Human Code Review
*   **协同作用：** `Cursor rules`和`memory_bank`是**“预防”**工具。`CI/CD Pipeline`是**“检测”和“门禁”**。`Human Code Review`是最终的**“纠正”和“深度验证”**。
*   **强制回归测试：** 每次自动生成或更新代码后，必须自动触发**全量回归测试**。
*   **自动化契约校验：** CI流程中必须增加接口契约与实现的自动化校验。

### 6. 强制唯一数据源与契约管理
*   **理念与必要性：** 必须建立“唯一数据源”原则，避免数据冗余与不一致。
*   **常量与状态码管理：** 集中定义在单一可信源文件。
*   **接口Schema与文档绑定：** 使用Pydantic等工具定义Schema，并自动导出OpenAPI/Swagger文档。

### 7. 统一自动化生成流程入口
*   **改进措施：** 所有自动化生成任务（如代码生成、文档生成、测试用例生成）必须通过统一的入口（如Makefile, build.py）进行管理和触发。
