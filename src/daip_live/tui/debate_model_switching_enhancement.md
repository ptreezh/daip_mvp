# 模块化TUI辩论模型切换显示功能 - 需求与设计文档

## 1. 需求文档

### 1.1 问题描述
在模块化TUI的多模型辩论功能中，虽然系统内部正确地为不同角色切换了AI模型，但状态栏没有实时显示当前辩论角色所使用的具体模型，导致用户无法直观了解当前辩论轮次中哪个角色使用了哪个模型。

### 1.2 功能需求
1. **模型切换通知**：在辩论过程中，当角色切换时，系统应更新状态栏以显示当前角色使用的模型
2. **状态栏实时更新**：状态栏应根据当前辩论角色动态显示对应的模型名称
3. **角色模型映射**：系统应能获取并存储每个角色对应的模型配置
4. **向后兼容**：在没有角色模型配置时，系统应使用默认模型显示

### 1.3 非功能需求
1. **性能**：状态更新不应影响辩论系统的响应速度
2. **稳定性**：功能应稳定，不能导致TUI崩溃
3. **可维护性**：代码应清晰易懂，便于后续维护

## 2. 设计文档

### 2.1 系统架构
- **DAIP_TUI**: 模块化TUI主控制类
- **EnhancedDebateManager**: 增强辩论管理器，支持多模型
- **RoleModelManager**: 角色模型管理器，管理角色-模型映射
- **状态栏系统**: 显示实时系统状态和模型信息

### 2.2 设计方案
采用事件驱动模式，通过辩论事件更新UI状态：
1. 当辩论管理器生成 `DebateTurnStartEvent` 事件时，TUI捕获该事件
2. 更新 `_current_debate` 中的 `role_models` 映射
3. 调用 `_update_current_model` 更新当前模型
4. 刷新状态栏显示

### 2.3 核心实现

#### 2.3.1 状态栏显示逻辑 (`get_enhanced_status_text`)
- 检查辩论是否活跃
- 如果活跃且有当前参与者，查找该角色对应的模型
- 显示格式：`{role_model} ({current_role})`

#### 2.3.2 事件处理 (`_handle_debate_event`)
- 处理 `DebateTurnStartEvent` 事件
- 更新当前参与者
- 根据角色模型映射更新当前模型
- 刷新状态栏

#### 2.3.3 模型更新 (`_update_current_model`)
- 更新内部模型变量
- 调用状态栏刷新方法

### 2.4 数据流程
1. `EnhancedDebateManager.run_debate()` 生成事件序列
2. 事件通过 `_handle_debate_event()` 处理
3. `DebateTurnStartEvent` 触发模型切换
4. `_current_model` 更新
5. `get_enhanced_status_text()` 生成新状态文本
6. 状态栏显示更新

### 2.5 错误处理
- 如果角色模型映射不可用，使用默认模型
- 如果状态栏更新失败，系统继续运行
- 辩论异常时，清理辩论状态

## 3. 测试策略
- **单元测试**：验证 `get_enhanced_status_text` 方法返回正确的模型显示
- **集成测试**：验证辩论事件处理更新模型状态
- **端到端测试**：验证整个辩论流程中的模型切换显示

## 4. 验证结果
- 状态栏正确显示 "Model: {role_model} ({role_name})" 格式
- 辩论过程中角色切换时模型信息实时更新
- 功能不影响系统性能和稳定性
