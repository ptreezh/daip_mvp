SOLID原则概述

SOLID是面向对象设计的五个基本原则的首字母缩写，由Robert C. Martin提出， 旨在创建更易理解、更灵活、更可维护的软件设计。

S - 单一职责原则 (Single Responsibility Principle)

定义：一个类或模块应该只有一个引起变化的原因。

❌ 违反单一职责原则

问题代码示例 
# 违反单一职责原则
class User:
    def __init__(self, name, email):
        self.name = name
        self.email = email
        self.db_connection = None
        self.logger = None
    
    # 用户数据管理职责
    def save_to_database(self):
        # 数据库操作
        pass
    
    def load_from_database(self, user_id):
        # 数据库查询
        pass
    
    # 日志记录职责
    def log_action(self, action):
        # 日志记录
        pass
    
    # 邮件发送职责
    def send_email(self, subject, message):
        # 邮件发送
        pass
    
    # 用户认证职责
    def authenticate(self, password):
        # 用户认证
        pass

✅ 遵循单一职责原则

实践要点：

  • 每个模块专注单一功能领域
  • 避免混合业务逻辑和技术实现
  • 便于测试和维护
  • 降低模块间耦合度

O - 开闭原则 (Open-Closed Principle)

定义：软件实体应该对扩展开放，对修改关闭。

❌ 违反开闭原则

问题代码示例 
# 违反开闭原则
class PaymentProcessor:
    def process_payment(self, amount, payment_type):
        if payment_type == "credit_card":
            # 处理信用卡支付
            return self.process_credit_card(amount)
        elif payment_type == "paypal":
            # 处理PayPal支付
            return self.process_paypal(amount)
        elif payment_type == "alipay":
            # 处理支付宝支付 - 新增功能需要修改原有代码
            return self.process_alipay(amount)
        else:
            raise ValueError("Unsupported payment type")
    
    def process_credit_card(self, amount):
        return f"Processed credit card payment: ${amount}"
    
    def process_paypal(self, amount):
        return f"Processed PayPal payment: ${amount}"
    
    def process_alipay(self, amount):
        return f"Processed Alipay payment: ${amount}"

✅ 遵循开闭原则

改进代码示例 
# 遵循开闭原则
from abc import ABC, abstractmethod

class PaymentProcessor(ABC):
    @abstractmethod
    def process(self, amount):
        pass

class CreditCardProcessor(PaymentProcessor):
    def process(self, amount):
        return f"Processed credit card payment: ${amount}"

class PayPalProcessor(PaymentProcessor):
    def process(self, amount):
        return f"Processed PayPal payment: ${amount}"

class AlipayProcessor(PaymentProcessor):
    def process(self, amount):
        return f"Processed Alipay payment: ${amount}"

# 扩展新的支付方式无需修改现有代码
class WeChatPayProcessor(PaymentProcessor):
    def process(self, amount):
        return f"Processed WeChat Pay payment: ${amount}"

class PaymentService:
    def __init__(self):
        self.processors = {}
    
    def register_processor(self, payment_type, processor):
        self.processors[payment_type] = processor
    
    def process_payment(self, amount, payment_type):
        if payment_type in self.processors:
            return self.processors[payment_type].process(amount)
        else:
            raise ValueError("Unsupported payment type")

实践要点：

  • 使用抽象和接口定义扩展点
  • 通过组合而非继承实现功能扩展
  • 预留配置化的扩展机制
  • 保持核心逻辑稳定

练习案例：报告生成系统

案例背景：

现有一个报告生成系统，可以根据不同格式（PDF、Excel、CSV）生成销售报告。 目前代码违反了多个SOLID原则，请对其进行重构。

  1. 分析原始代码违反了哪些SOLID原则

from abc import ABC, abstractmethod

# S - 单一职责原则：分离不同职责
class DataProvider:
    def load_data(self):
        # 专门负责数据加载
        return []

class ReportFormatter(ABC):
    @abstractmethod
    def format(self, data):
        pass

class PDFFormatter(ReportFormatter):
    def format(self, data):
        return "PDF Report Content"

class ExcelFormatter(ReportFormatter):
    def format(self, data):
        return "Excel Report Content"

class CSVFormatter(ReportFormatter):
    def format(self, data):
        return "CSV Report Content"

class FileStorage:
    def save(self, content, filename):
        # 专门负责文件存储
        pass

class EmailService:
    def send(self, recipient, content):
        # 专门负责邮件发送
        pass

# O - 开闭原则：易于扩展新的格式
class ReportGenerator:
    def __init__(self, data_provider, formatter, storage, email_service):
        self.data_provider = data_provider
        self.formatter = formatter
        self.storage = storage
        self.email_service = email_service
    
    def generate(self):
        data = self.data_provider.load_data()
        content = self.formatter.format(data)
        return content
    
    def save_report(self, content, filename):
        self.storage.save(content, filename)
    
    def send_report(self, content, recipient):
        self.email_service.send(recipient, content)

# L - 里氏替换原则：子类可以替换父类
# I - 接口隔离原则：每个类只依赖需要的接口
# D - 依赖倒置原则：依赖抽象而非具体实现
违反的SOLID原则分析：
  • S - 单一职责原则：ReportGenerator类承担了太多职责（数据加载、格式化、文件保存、邮件发送）
  • O - 开闭原则：添加新的报告格式需要修改现有代码
  • D - 依赖倒置原则：直接依赖具体实现而非抽象
